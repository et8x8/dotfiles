# update-implementation (Implementation 工程)

Test 工程で生成された (失敗状態の) テストを通すコードを実装する。

## 入力

- `docs/spec/` 配下のすべての Spec ファイル
- Test 工程で生成 / 更新されたテストコード
- 既存のプロダクションコード

## 出力

プロダクションコード。配置先・命名規則は**プロジェクトの規約に従う** (`AGENTS.md` / 既存コードを参照)。

## 手順

### 1. 入力の理解

1. Spec を全部読む。
2. Test を全部読む (期待される入出力 / 振る舞いを把握)。
3. 既存プロダクションコードを読み、変更が必要な範囲を特定する。

### 2. 実装

各 REQ に対し、テストを通すための実装を行う。

- **追加された REQ** → 新規実装。
- **変更された REQ** → 既存コードを編集。
- **削除された REQ** → 不要になったコードを**削除する**。

実装中は以下を厳守する:

- Spec / Test に記載のない振る舞いを実装しない。
- Spec / Test と矛盾する実装をしない。
- **互換性 / フェイルセーフは Spec に記載されている場合のみ**実装する。Spec にない後方互換コードは入れない。
- 「将来使うかもしれない」変数 / 関数 / メソッド / クラスは作らない。残さない。
- 未使用の import / 変数 / 関数を削除する。

### 3. 成功確認 (重要)

**実装後、テストを実行し、すべて成功することを確認する**。

1. プロジェクトのテストコマンドを実行 (例: `pytest`, `npm test`, `go test ./...`)。
2. **対象の新規 / 変更テスト**がすべて成功 (PASS) することを確認する。
3. **既存のテスト**が回帰していない (壊していない) ことも確認する。
4. 失敗が残る場合:
   - 実装の不備 → 実装を修正して再実行。
   - テストが間違っている (実装の都合で書き換えたい) → **禁止**。Spec に立ち返り、必要なら ADR から見直す。`/spec` または `/adr` に戻る。

実行結果 (PASS 数 / FAIL 数 / 該当テストの ID) をユーザーに簡潔に報告する。

### 4. クリーンアップ

- リンタ / フォーマッタを実行し、ワーニングを解消する (プロジェクト規約に従う)。
- 未使用コード (import / 変数 / 関数 / クラス) を削除する。
- デバッグ用 print / console.log を削除する。
- TODO / FIXME コメントは Spec に立ち返るべき内容なら削除し、Spec / ADR に反映する。

### 5. 検証

- すべての対象テストが PASS しているか?
- Spec / Test と矛盾する実装はないか?
- Spec にない互換性 / フェイルセーフコードを入れていないか?
- 未使用コードは残っていないか?
- リンタ / フォーマッタは通っているか?

## やってはいけないこと

- Spec / Test に記載のない実装をする。
- Spec / Test と矛盾する実装をする。
- 実装に合わせて Test を書き換える (Spec を直すなら ADR から見直す)。
- Spec にない互換性 / フェイルセーフを実装する。
- 「将来使うかもしれない」未使用コードを残す。

## 完了後

すべてのテストが通ったら、`/document` を呼び出して Document 工程に進む。
