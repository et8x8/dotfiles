# ADR: 二胡用数字譜 Web アプリ (編集・管理・再生・印刷)

- ステータス: Draft
- 日付: 2026-05-17
- 起案者: Agent (Composer)

## Context

二胡向け**数字譜**（簡譜系の番号表記と二胡特有の奏法記号を含む）を、ブラウザ上で**作成・編集・管理・簡易再生・印刷／PDF 出力**できる Web アプリを新規に構築する。表現力は可能な限り広く（音楽記号・奏法・転調・複数パート等）取り込みつつ、**八分音符・十六分音符、三連符（三連複）、小節線、小節の繰り返し記号**を MVP 必須の表現として扱い、**装飾音および強弱・コーダ等の音楽記号は後述の個別一覧に列挙した種別ごとに** MVP で扱う。楽譜データは**アカウント単位でクラウド保存**する。**共有 URL や public 公開は設計対象外**（著作権・運用負荷の回避）。再生は簡易でよい。

拍子については、**第1小節には必ず拍子記号を明示する**（省略しない仕様）。第2小節以降は、**直前小節までで有効な拍子**と、**当該小節の内容（音符・休符・三連符グループ・MVP 装飾音各種等から算出した拍数）**が一致していれば**拍子表記を省略**できる。一致しない小節は**当該小節を警告表示**（例: 背景を黄色）し、**自動では解決しない**（ユーザーが編集で解消する前提）。

デプロイ先は **Cloudflare Workers** とし、**2026 年時点の Cloudflare Pages と Workers が統合された最新運用**（単一プロジェクトで静的アセットと Worker ルートを一体管理）を前提とする。

加えて、楽譜グリッド外の**任意位置へのテキスト・画像配置**（注釈・表紙・図版等）を許可する。

## Decision

### アーキテクチャ概要

- **フロントエンド**: SPA（推奨: React + TypeScript + Vite）。楽譜エディタ UI、クライアント側の簡易再生、印刷用レイアウトを担当。
- **バックエンド / ホスティング**: **Hono**（または公式 Router）を **Cloudflare Workers** 上に配置。同一リポジトリ・同一 `wrangler` プロジェクトで **静的アセット**（SPA ビルド成果物）を配信し、**API は Worker ルート**に集約する（Pages 統合後の標準パターンに合わせる）。
- **認証**: **セッション方式**（httpOnly Cookie + サーバ側セッションストア）。パスワードハッシュは **Argon2id**（Workers 対応ライブラリ／WASM 等で実装）。将来の SSO は別 ADR で拡張可能とする。
- **永続化**:
  - **Cloudflare D1**: ユーザー、楽譜メタデータ、**バージョン付き楽譜ドキュメント JSON**（サイズ上限内を原則）、テキスト／画像アノテーションのメタデータと配置情報。
  - **Cloudflare R2**: **画像バイナリ**および**大きな添付**（D1 の行サイズに収まらない場合のオフロード）。オブジェクトキーは常に `userId` プレフィックス下に限定し、**他ユーザーからの直接参照不可**（署名付き URL は「本人ダウンロード用」のみ、**匿名公開は実装しない**）。
- **楽譜ドキュメントモデル**: **バージョン付き JSON スキーマ**（例: `schemaVersion`）で表現。トップレベルに以下を含む設計とする。
  - **パート配列**: 各パートにトラック種別（二胡主旋律等）、**相対音高の数字譜**（音階・八度・**MVP 装飾音各種**）、**奏法・弓法・指法**タグ、**小節区切りと小節線**、**八分・十六分などの音価**、**三連符（三連複）グループ**、**小節繰り返し記号**、**MVP 音楽記号各種**（強弱・コーダ等）および**任意の拡張記号アトミック**の列。
  - **転調**: グローバルおよびパートローカルの**調号／移調量**を明示的フィールドで保持（再生・印刷で一貫して解釈）。
  - **拍子**: 楽曲先頭の**第1小節は必ず拍子記号を表示**する。以降の各小節では、**直前までに確定している拍子**（第1小節の明示、またはユーザーが途中で挿入した拍子変更）を基準に、**当該小節内の音符・休符・三連符グループ・MVP 装飾音各種等から算出した拍数**とを比較する。**一致すれば拍子表記を省略**し、**不一致なら警告スタイル**（例: 背景 `#fff3cd` 系）を適用する。**自動補正は行わない**。拍数算出はクライアント／サーバで同一ルールとする。
  - **フリーレイヤー**: 楽譜座標系に対する**絶対配置**のテキストボックス・画像参照（R2 object id + 変換行列）を別レイヤーとして保持（z-index / ロック可否）。
- **再生**: **Web Audio API** ベースの軽量シンセ（簡易正弦／フォルマント寄りの倍音叠加でも可）。**厳密な二胡物理モデリングは必須としない**。MIDI 互換の完全性も求めない。拍子・テンポに沿ったイベントスケジューリングを行い、**八分・十六分・三連符**、**装飾音・音楽記号の再生**、**小節繰り返しの反復展開**は **`docs/spec/erhu-numeric-notation-webapp.md` の「再生解釈（MVP・仕様固定）」「三連符の拍数（MVP）」「小節繰り返しの再生（MVP）」**に従う。
- **印刷 / PDF**: まず **専用印刷ビュー**（`@media print`）とブラウザの「PDF として保存」を正とする。品質要件が上がった場合は別 ADR で**サーバ／クライアント PDF 生成**を検討。

### 非機能・スコープ境界

- **共有・コラボ・公開リンク**: **実装しない**（API に public read を持たせない）。
- **著作権監査・コンテンツモデレーション**: スコープ外（利用規約テキストは別途最小限でも可）。
- **拍子矛盾の自動解決**: **禁止**（警告のみ）。

### 記号・表現の「可能な限り」の扱い

- データモデルは**拡張可能なタグ列＋ベンダ中立の記号コード**（内部コード表）で設計する。
- **MVP 実装セット**（必ず動く記号の最小集合）を定義し、**少なくとも**次を含む: **八分音符・十六分音符**、**三連符（三連複）**、**小節線**、**小節の繰り返し記号**、および既存の休符長・付点・連桁等。**装飾音および音楽記号は、下記「MVP: 装飾音の個別対象」「MVP: 音楽記号の個別対象」に列挙した種別をそれぞれ個別の仕様項目として含み**、総称だけで省略しない。それ以外は**レンダリング上グレーアウト／未対応マーク**でもよいが、**データとしては保存可能**にする（前方互換）。
- 上記 MVP 一覧に**未掲載**の一般的記号（例: 弓向き、指番号、重音、反復以外の記号、自由節マーク等）は**チェックリスト化**し、実装フェーズで優先度付けして Spec に落とす。

### MVP: 装飾音の個別対象

MVP では次の装飾音を**それぞれ別仕様**（入力・譜面表示・JSON 保存・拍数寄与・再生解釈）として扱う。

- **前倚音**
- **後倚音**
- **波音**
- **逆波音**
- **回音**
- **顫音**（`tr` に相当する揺れ。長さは主音の音価に紐づける）
- **上滑音**・**下滑音**（滑音）
- **打音**

### MVP: 音楽記号の個別対象

MVP では次の音楽記号・演奏指示を**それぞれ別仕様**として扱う。強弱の保存値、速度語の許可集合と正規化、再生時のゲイン・BPM・フェルマータ伸長、コーダ類の未ジャンプ方針、小節繰り返しの種別コード（`repeatOneBar` / `repeatTwoBars`）および展開手順の**数値仕様の正本は `docs/spec/erhu-numeric-notation-webapp.md` の対応節**とする（本節は列挙のみ）。

- **強弱記号**: `pp`, `p`, `mp`, `mf`, `f`, `ff` の 6 段階のみ（Spec にゲイン倍率表あり）。
- **フェルマータ**（取り止め）
- **コーダ記号**
- **セーニョ（Dal Segno）記号**
- **ファイン（Fine）**
- **ダブルバー**（区画終端。小節線とは別表現でもよい）
- **速度・表情指示**: Spec「許可される速度・表情テキスト（MVP）」に列挙した語のみ保存可。正規化手順は Spec に従う。

## Acceptance criteria

1. ログイン済みユーザーのみが、**自分の楽譜一覧**を閲覧・新規作成・削除（論理削除可）できる。
2. エディタで**二胡用数字譜**を入力・編集でき、**小節・小節線・拍子・四分を基準とする音価・八分音符・十六分音符・三連符（三連複）・休符・八度・小節の繰り返し記号**を MVP で表現できることに加え、**装飾音および音楽記号は ADR の「MVP: 装飾音の個別対象」「MVP: 音楽記号の個別対象」に列挙した種別をそれぞれ個別に** MVP で表現できる。
3. **転調**（楽曲全体またはパート単位）を指定すると、**編集画面・再生・印刷**のいずれでも一貫した音高解釈になる。
4. **複数パート**を保持でき、パートごとに表示のオン／オフと縦／横の基本レイアウト規則が定義されている。
5. **任意位置のテキスト・画像**を配置・移動・削除でき、楽譜データに保存され、再読込で復元される。
6. **簡易再生**が可能で、テンポ・拍子に沿って**明らかに聴き取れる音程順序**が鳴る（音質は簡易で可）。**八分・十六分・三連符**および **装飾音・音楽記号の再生**は **`docs/spec/erhu-numeric-notation-webapp.md` の「再生解釈（MVP・仕様固定）」「三連符の拍数（MVP）」「小節繰り返しの再生（MVP）」**に従い、**小節繰り返しは反復展開後のタイムライン**でスケジューリングする。
7. **印刷用ビュー**からブラウザ印刷／PDF 保存で、**小節線・小節繰り返し記号・MVP 装飾音各種・MVP 音楽記号各種・警告背景・フリーレイヤー**が破綻なく出力される。
8. **拍子表記ルール**: **第1小節には常に拍子記号を表示**する。第2小節以降は、**直前まで有効な拍子**と**当該小節の内容（音符・休符・三連符グループ・MVP 装飾音各種等から算出した拍数）**が一致するときのみ、**拍子表記を省略**できる UI 仕様が実装されている。
9. **拍子警告**: **直前まで有効な拍子**と**当該小節の内容から算出した拍数**が一致しない場合、当該小節に**黄色系の警告背景**が付き、**システムは自動修正しない**（ユーザー編集が必要）。
10. すべての API が **認証必須**であり、**他ユーザーの楽譜・オブジェクトにアクセスできない**（ID 推測含めサーバ側で拒否）。
11. **Cloudflare Workers 統合環境**へデプロイでき、静的 SPA と API が同一プロジェクトで動作する。

## Consequences

- **長所**: 運用コスト低・スケール容易・アカウント境界がデータモデルと一致しやすい。
- **短所**: 楽譜エディタ UI の実装コストが高い。記号の網羅はデータモデル先行で段階的実装になり、初期リリースでは「表示のみ／一部編集不可」が混在しうる。
- **リスク**: 拍数算出（付点・連桁・タイ、**八分・十六分**、**三連符**、**装飾音（個別種別ごとの拍寄与）**等）の解釈差が警告の過多／過少を生むため、**算出根拠をデバッグ表示**する開発者向けオプションを検討余地あり（本 ADR では必須としない）。

## Alternatives

| 代替案 | 却下理由 |
| --- | --- |
| フロントのみ LocalStorage | クラウド保存・マルチ端末要件に反する |
| Supabase / Firebase | デプロイ先を Cloudflare に固定する方針に反する |
| サーバサイド PDF 必須 | 初期コスト大。ブラウザ印刷で足りる段階を先に確かめる |
| 拍子矛盾の自動補正 | ユーザー要求で明示的に禁止 |
| 楽譜の公開コミュニティ機能 | スコープ外 |
